## Disposition of `37d760b` and the four undocumented deferrals

| Item | Disposition | Audit result |
|---|---|---|
| `37d760b`: publish the full committed identity | **PARTLY FIXED; not sufficient to accept** | The five projection fields are numerically correct in the quiescent production DB path, and no callback runs before `CommitAudioProjections` returns the full count. They are not read back from the committed row: `Section` comes from `intent.Section` and the other fields come from the local pre-commit `rows` slice. Production happens to preserve those values because its commit updates only `state` and `updated_at_ns`. The live path still does not perform restart's eager inode registration, is published one row at a time, can be overwritten by the concurrent startup whole-set publish, and has incomplete/racy directory-cache invalidation. A successful live Add therefore still does not provide the same scanner-visible identity/coherence as restart. |
| `37d760b`: contain rollback pruning in `SectionWriter` | **REJECTED** | Static outward/inward symlinks are now refused, which is real progress. The new dirfd prune can nevertheless remove a directory after its opened parent is relocated outside the section, a case the pathname implementation would leave alone. It also intentionally deletes pre-existing empty ancestors (new test C17c requires this), and unwind logs prune/removal errors but still deletes the registry ownership rows. The commit did not establish either rename-race containment or ownership-safe rollback. |
| Round-2 finding 8: hash/magnet mismatch | **SHIP BLOCKER; the lead's deferral judgment is wrong** | This is the authoritative torrent identity boundary for Add and Inspect. Supplying hash A with a magnet for B mutates/wakes B instead of returning the mandatory `400 hash_magnet_mismatch` with no mutation. It is not a response-shape nicety and is not defensible as an undocumented PR 3 carry. |
| Round-2 finding 9: all-present replay response | **Not a blocker alone, but the undocumented deferral is not defensible** | The endpoint still returns `201`, omits `already_present`, omits stable `mtime`, and says `status` rather than the specified `state`. That contradicts spec §6.4 and the public README. It can be carried only as an explicit API incompatibility; silently handing it to the human as complete is wrong. |
| Round-2 finding 10: body cap and unknown fields | **Not a blocker alone, but the undocumented deferral is not defensible** | The 1 MiB allocation bound is real, but the full-request limit is not: a valid JSON value ending at byte 1 MiB plus arbitrary excess bytes is accepted and can mutate state. Audio also still accepts unknown fields despite the explicit strict-decoding MUST. Both remain untested at the handler boundary. |
| Round-2 finding 11: `omitempty` on absent external identity | **LOW; technically deferrable, but only if documented** | This does not corrupt content identity, but it directly contradicts the accepted review ruling that Add returns both keys as empty strings, like List. The separate differing-identity replay policy is documented for PR 3; this response-shape defect is not. |

## Locked-suite weaknesses, rechecked

- `audio-live-publication` gained P10/P11, but both terminate at a fake `PublishAudioPath` callback and fake registry. They prove distinct non-zero fields are passed; they do not call `globalAudioNamespace.AddProjection`, update the real inode map, run Readdir/Lookup/Getattr/Open, exercise startup/live races, or exercise the real directory cache. The producer is still not joined to the production consumer.
- The real VFS identity tests in `main_test.go` manually publish rows into their fixture. They prove that a fully populated namespace is consumed correctly, not that Add produces all live side effects restart produces.
- `audio-path-containment` C17 proves static symlinks are refused and normal empty chains are pruned, but has no component rename/exchange race. C17c affirmatively locks in deletion of a pre-existing empty ancestor.
- `audio-atomic-add` still has no process-death/restart, post-create write/sync failure, rollback cleanup failure, leaf substitution, or created-directory ownership fixture.
- `startup-read-failure` still releases the blocked fake Wake during cleanup and counts only handles/pumps/master slots/sessions. It cannot see a detached production activation or occupied native Wake semaphore.
- `audio-external-identity-api` still omits the no-identity Add JSON shape and differing-identity replay case.
- The workflow wiring guards all pass, but the live-publication guard remains syntactic: it cannot distinguish namespace-only publication from restart-equivalent namespace plus inode/cache publication.

## Checked and found CORRECT

- The live projection's scalar fields agree with the production committed row under current DB semantics. Hash is the engine-reported canonical identity stored in `row.Hash`; `FileIndex` is the positive 1-based GoStorm ID stored as the same Go `int`; `Size` is the same byte count stored as `int64`; `MtimeNS` is one `time.Now().UnixNano()` value stored in `mtime_ns` and reconstructed with `time.Unix(0, ns)`; section and virtual path retain their stored spelling. There is no seconds/nanoseconds or zero/one-based conversion mismatch.
- Live publication occurs only after every rename and after `CommitAudioProjections` returns without error and with exactly `len(rows)` affected. No normal row identity is published before the commit that makes it authoritative.
- Startup namespace construction copies the same five persisted fields and publishes only rows accepted by reconciliation. Its whole-set `Publish` is atomic to namespace readers; the defect is its race with live inserts and the missing equivalent live inode/cache side effects, not torn projection structs.
- `AudioNamespace.AddProjection`, `Publish`, and `Lookup` copy whole value structs while holding the namespace mutex. Concurrent readers cannot observe a half-written hash/index/size/mtime tuple.
- `SectionWriter` remains open during every in-process unwind: `defer writer.Close()` is installed before staging, and deferred close runs only after the return completes. If `OpenSectionWriter` itself fails, no registry row or request-created filesystem object exists yet; the newly hydrated torrent is abandoned.
- A registry staging error occurs before any stub write. The production `StageAudioProjections` transaction rolls back atomically on insert/commit error.
- For an ordinary, unraced real-directory chain, the new prune removes empty parents up to but not including the root. ENOTEMPTY/EEXIST stops at a directory still in use; static inward/outward symlinks are refused; invalid relative paths and use-after-close are rejected. No ordinary directory that the pathname version cleaned was found to leak. The failures are ownership and relocation races, not the basic walk.
- `RENAME_NOREPLACE`, exclusive staging creation, static no-symlink walking, and refusal to replace an already occupied final remain correct. A normal second-rename failure occurs before registry commit and the ordinary cleanup path removes the first final and the remaining staged names.
- Audio metadata and Open consume the namespace's hash/index/size/mtime rather than trusting a replaced physical stub. With a correctly populated namespace, Readdir/Lookup/Getattr/Open agree on content and a malformed/replaced stub cannot retarget the stream.
- The audio target uses the registry URL index without resident-file guessing and rejects non-positive indices. The index is passed through unchanged.
- Video's supported-path behavior remains the legacy behavior: copy-before-sort preserves the engine slice; the natural comparator, one-based sorted indices, name normalization, unique-size match, and positive URL-index fallback agree with the old resolver. The new explicitly tested malformed case of no heuristic match and no usable URL index now returns an error where the old code returned `(hash,0,nil)`; that is deliberate fail-closed hardening, not byte-equivalence for malformed input. No `37d760b` behavior change affected video.
- Immediate activation failures and exhausted demand reads terminate with `EIO`; a failed cold Open publishes no handle, pump, master slot, playback entry, tail target, or TTFF session. The remaining cancellation leak is limited to detached Wake/activation work and its semaphore token.
- External identity still validates both-or-neither, normalizes two whitespace-only values to absence, rejects a half pair, preserves nonblank opaque bytes, and carries them through row, stub, non-empty Add response, List, migration, and reconciliation. Identity does not become a uniqueness key or replace `(hash,file_index)`.
- `94c6011` and `f83810a` are comment-only commits and changed no behavior. All production comment blocks those commits touched are at most two lines. The remaining violations are the separately blamed PR test comments listed in finding 12, not `68c9626` or upstream-merge comments.
- The deliberately carried hot-path copy/sort remains exactly as documented; audio still allocates and sorts the resident list before discarding it. Audio Remove still does not unpublish, `WriteAudioStub` remains unreachable, directory fsync remains absent, and differing external-identity replay still returns the stored pair. These are real carried items, not newly claimed fixes.
