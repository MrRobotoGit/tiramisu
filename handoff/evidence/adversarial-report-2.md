## Locked-suite weaknesses found

- `audio-live-publication` P1/P2/P9 assert only that a path-only callback fired and in what order. They do not assert the callback carries hash/index/size/mtime or exercise production Readdir → Lookup → Getattr → Open, so the zero-identity production wiring passes.
- `audio-path-containment` covers static symlinks thoroughly but explicitly accepts a symlinked root and never races rename/exchange of an already-open directory. Cleanup's pathname-based `pruneEmptyDirs` is outside the suite's surface.
- `audio-atomic-add` covers injected rename and commit returns, not process death, restart recovery, directory durability, post-create write/sync failure, rollback substitution, or ownership of pre-existing directories.
- `startup-read-failure` releases its blocked Wake in test cleanup and counts only handles/pumps/master slots/sessions. A detached activation goroutine and occupied Wake semaphore therefore pass vacuously.
- `audio-external-identity-api` asserts absent keys for stubs and unconditional empty keys for List, but not the accepted unconditional empty-key rule for Add; it also has no differing-identity replay test.
- The workflow wiring checks are syntactic. They report “committed audio projection is published” even though production publishes only path membership and destroys the identity required by the VFS.

No contradictory expectations were found between the locked slices. The principal problem is weaker fixtures: unit hooks prove calls in isolation while never joining the producer to the real FUSE consumer.

## Checked and found correct

- `SectionWriter` rejects invalid relative paths, static outward and inward descendant symlinks, symlink leaves, existing staged leaves, and existing final destinations. `RENAME_NOREPLACE` preserves the old final and leaves the staged file for rollback.
- Ordinary descriptor/error paths in `OpenSectionWriter`, `openParent`, `WriteStaged`, `Publish`, and `RemoveStaged` close their fds; operations after `Close` fail rather than using a recycled descriptor.
- A normal second-rename failure occurs before registry commit and removes previously renamed finals/staging rows. The new order fixes the exact in-process partial-rename failure from round 1.
- Startup publication after a full reconciliation carries full row identity. `stubMeta` derives audio metadata from the committed namespace, so a modified physical stub cannot redirect a reconciled projection.
- `ResolveOpenTarget` uses the supplied registry-derived index for music/audiobooks, including equal-size/name traps and absent resident lists. It errors on a non-positive audio index.
- Video target semantics are byte-equivalent to the old `resolveTargetFile`: same natural sort comparator, same one-based sorted indices, same name normalization/suffix rules, same unique-size fallback, and same URL-index fallback. Copy-before-sort also removes mutation of the engine's shared slice.
- Movie/TV list routing and stub metadata remain on the legacy paths. Movie/TV Open intentionally receives the same terminal `EIO` policy required by the PR 2 engine-wide startup-read addendum; EOF still returns empty success and context cancellation in the tested cold/read paths returns `EINTR`.
- A cold Open whose activation returns an error creates no handle, pump, master slot, playback entry, tail target, or TTFF session. Exhausted bounded reads now return non-retryable `EIO`, and a later independent attempt is not poisoned.
- External identity validation correctly implements both-or-neither; two whitespace-only values normalize to absent; one whitespace-only half with a real other half is 400; nonblank padded/opaque values are preserved byte-for-byte. Row, stub, response (when present), List, migration, and reconciliation carry the pair. Identity is not made unique and does not replace `(hash,file_index)`.
- A differing identity on an already-present projection is not silent to an API client: Add echoes the stored identity. Treating update/conflict semantics as PR 3 is an explicit maintainer ruling, not an invented PR 2 behavior.
- Audio Remove/unpublication is not implemented and no production caller invokes `AudioNamespace.Remove`. That is a real lifecycle gap, but the roadmap explicitly assigns exact-path Remove to PR 3, so it is not charged here as a PR 2 regression. Until then, no claim that live removal is coherent is supportable.
